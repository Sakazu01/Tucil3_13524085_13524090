\section{PENDAHULUAN}

\subsection{Latar Belakang}
Permasalahan pencarian rute (\textit{pathfinding}) merupakan salah satu topik fundamental dalam bidang kecerdasan buatan dan strategi algoritma. Dalam konteks pengembangan permainan video, \textit{pathfinding} sering dimodifikasi dengan berbagai aturan fisika maupun logika lingkungan. Salah satu contoh penerapannya adalah pada \textit{Ice Sliding Puzzle}, di mana entitas yang bergerak tidak dapat berhenti secara bebas di setiap koordinat, melainkan akan terus meluncur hingga menabrak objek penghalang. Mekanika ini mengubah topologi graf ruang status (\textit{state space}) dari pencarian rute tradisional, sehingga memerlukan penyesuaian dalam pembangkitan simpul (\textit{node generation}) dan perhitungan biaya lintasan. 

\subsection{Deskripsi Tugas/Permasalahan}
Tugas ini menuntut penyelesaian permainan \textit{Ice Sliding Puzzle} pada matriks berukuran $N \times M$. Aktor memulai pergerakan dari koordinat \texttt{Z} (awal) dan harus mencapai titik \texttt{O} (tujuan). Papan terdiri dari lantai biasa dengan bobot lintasan yang berbeda-beda, dinding penghalang (\texttt{X}), bahaya mematikan (\texttt{L} / Lava), serta titik pemeriksaan angka (\textit{checkpoint}).

Aktor dapat bergerak ke empat arah kardinal. Saat bergerak, aktor terus meluncur tanpa henti hingga menabrak dinding, batas luar peta, atau \textit{checkpoint} yang belum saatnya dikunjungi (berlaku sebagai dinding). Gerakan dinyatakan ilegal apabila aktor melintasi lava, tidak bergerak dari posisi awal, atau mengakhiri luncuran di titik tujuan sebelum seluruh \textit{checkpoint} dikumpulkan secara berurutan.

\subsection{Tujuan}
Tujuan dari pengerjaan tugas ini adalah:
\begin{enumerate}[noitemsep]
    \item Memodelkan \textit{Ice Sliding Puzzle} ke dalam representasi ruang status yang valid.
    \item Mengimplementasikan algoritma pencarian rute berinformasi (A*, GBFS) maupun tidak berinformasi (UCS, BFS, IDA*).
    \item Merancang dan menganalisis fungsi heuristik untuk mengevaluasi efisiensi pencarian rute optimal.
\end{enumerate}

\section{TEORI DASAR}

\subsection{Konsep \textit{Pathfinding}}
Pencarian rute (\textit{route/path planning}) adalah proses algoritmik untuk menemukan lintasan dari satu simpul awal ke simpul tujuan dalam sebuah graf ruang status. Lintasan dikatakan optimal jika memiliki akumulasi bobot (biaya) paling minimum. Dalam kasus ruang status yang besar, pencarian rute dikendalikan melalui ekspansi simpul secara sistematis untuk mencegah iterasi yang berulang (siklus) dan memastikan program terminasi \cite{Munir1}.

\subsection{Algoritma A* (\textit{A-Star}) / UCS / BFS}
\begin{itemize}[noitemsep]
    \item \textbf{\textit{Uniform Cost Search} (UCS):} Merupakan perluasan dari algoritma Dijkstra. UCS mengekspansi simpul berdasarkan bobot lintasan aktual yang paling kecil dari titik awal.
    \item \textbf{\textit{Breadth-First Search} (BFS):} Melakukan ekspansi level demi level (menggunakan antrean FIFO). Optimal hanya jika seluruh bobot sisi bernilai sama (atau jika mencari jumlah pergerakan terminimum).
    \item \textbf{A* (\textit{A-Star}):} Algoritma hibrida yang menggabungkan biaya aktual dari asal dan estimasi biaya ke tujuan. A* menggunakan senarai prioritas dan dijamin optimal jika estimasi tidak pernah melebih-lebihkan biaya aslinya \cite{Munir2}.
\end{itemize}

\subsection{Fungsi Heuristik}
Fungsi heuristik, disimbolkan dengan $h(n)$, merupakan tebakan matematis terukur mengenai sisa biaya dari status $n$ ke status tujuan. Heuristik dimanfaatkan sebagai fungsi pandu untuk memotong ruang pencarian agar algoritma tidak menelusuri simpul yang tidak relevan. Heuristik yang baik harus bersifat \textit{admissible} (dapat diterima) agar solusi akhir dijamin optimal.

\section{IMPLEMENTASI ALGORITMA}

\subsection{Penjelasan Algoritma}
Pencarian rute dilakukan dengan langkah-langkah sistematis sebagai berikut:
\begin{enumerate}[noitemsep]
    \item \textbf{Inisialisasi:} Status awal didefinisikan sebagai $(X_z, Y_z, \text{index}_{cp}=0)$. Masukkan status ini ke dalam senarai prioritas dengan status belum dikunjungi.
    \item \textbf{Ekstraksi Simpul:} Ambil status dengan prioritas tertinggi. Jika algoritma A*, kriteria prioritas adalah $f(n)$ terkecil. Tandai status ini sebagai telah divisitasi.
    \item \textbf{Pemeriksaan Tujuan:} Jika aktor berada di \texttt{O} dan semua \textit{checkpoint} telah terkumpul, kembalikan lintasan dan hentikan pencarian.
    \item \textbf{Pembangkitan Suksesor (Mekanika Meluncur):}
    \begin{itemize}[noitemsep]
        \item Untuk setiap arah (Atas, Bawah, Kiri, Kanan), gerakkan aktor ubin demi ubin.
        \item Evaluasi ubin di depan. Jika berupa dinding, luar papan, atau \textit{checkpoint} dengan indeks yang lebih besar dari target, hentikan luncuran tepat di ubin saat ini.
        \item Jika lintasan mengenai lava (\texttt{L}), abaikan suksesor ini (tidak valid).
        \item Jika berhenti tepat di posisi awal sebelum meluncur, abaikan suksesor ini.
    \end{itemize}
    \item \textbf{Evaluasi Biaya:} Hitung akumulasi biaya ubin lantai yang dilintasi selama luncuran sebagai bobot langkah.
    \item \textbf{Pembaruan Senarai:} Masukkan status suksesor ke senarai prioritas untuk diekspansi pada siklus berikutnya. Ulangi ke langkah 2.
\end{enumerate}

\subsection{Analisis Teoritis}

\subsubsection{Definisi $f(n)$ dan $g(n)$}
Dalam penyusunan algoritma pencarian di atas:
\begin{itemize}[noitemsep]
    \item $g(n)$: Biaya lintasan nyata berupa akumulasi beban ubin dari posisi awal ke simpul $n$. Pada awal permainan, $g(start) = 0$.
    \item $h(n)$: Estimasi sisa biaya dari simpul $n$ menuju target selanjutnya (\textit{checkpoint} berikutnya atau tujuan \texttt{O}).
    \item $f(n)$: Nilai evaluasi gabungan penentu prioritas antrean. Pada A*, $f(n) = g(n) + h(n)$. Pada UCS, $f(n) = g(n)$. Pada GBFS, $f(n) = h(n)$.
\end{itemize}

\subsubsection{Analisis Admissibility Heuristik}
Sebuah heuristik $h(n)$ dinyatakan \textit{admissible} jika dipastikan $h(n) \leq h^*(n)$, dengan $h^*(n)$ adalah biaya murni/aktual ke tujuan.
Dalam implementasi ini, dibuat 3 tingkat heuristik:
\begin{enumerate}[noitemsep]
    \item \textbf{H1 (Jarak Manhattan):} Jarak geometris ke target dikalikan dengan bobot ubin paling murah di peta. Karena rute aktual pasti membutuhkan minimal sejumlah ubin tersebut dan tidak mungkin berbiaya di bawah harga ubin termurah, H1 mutlak \textit{admissible}.
    \item \textbf{H2 (\textit{Minimum Slide}):} Simulasi BFS ringan untuk mengetahui jumlah minimal aksi tarikan meluncur ke target. Jumlah tarikan dikali bobot ubin termurah tidak mungkin melebihi biaya lintasan aslinya.
    \item \textbf{H3 (Dijkstra Lokal):} Simulasi jalur ke target "selanjutnya" menggunakan aturan gerak penuh. Mengingat H3 hanya menghitung ke \textit{checkpoint} terdekat (bukan tujuan akhir keseluruhan permainan), nilainya dipastikan selalu $\leq$ rute total aslinya.
\end{enumerate}

\subsection{Analisis Hasil}
Dari rangkaian pengujian di atas, terlihat beberapa pola yang konsisten:

\begin{enumerate}[noitemsep]
    \item \textbf{Optimalitas cost.} UCS dan A* selalu menghasilkan cost minimum pada seluruh testcase yang punya solusi. BFS menghasilkan jumlah gerak terkecil, tetapi costnya bisa lebih besar---pada testcase6 misalnya, BFS menemukan solusi 13 gerak dengan cost 218, sementara UCS butuh 14 gerak untuk cost yang lebih kecil, yakni 217.
    \item \textbf{Efisiensi ekspansi.} GBFS secara konsisten menjelajahi simpul paling sedikit. Pada peta besar 30$\times$30 (testcase9), GBFS-H2 hanya butuh 74 iterasi dibanding 311 pada UCS. Trade-off-nya, GBFS-H2 menghasilkan cost 1385---lebih besar 5,5\% dari optimal.
    \item \textbf{Pengaruh kualitas heuristik pada A*.} H3 menghasilkan iterasi paling sedikit (149) karena estimasinya paling ketat. Meski overhead per-node lebih tinggi akibat Dijkstra internal, total waktu eksekusi A*-H3 (26 ms) tetap lebih cepat dari A*-H2 (31 ms) pada testcase9 berkat penghematan iterasinya.
    \item \textbf{Kasus tanpa solusi.} Testcase10 memiliki goal yang terkepung lava. Semua algoritma mengeksplorasi tepat 14 simpul yang dapat dijangkau sebelum ruang pencarian habis, membuktikan implementasi menangani kasus ini dengan benar.
\end{enumerate}

\section{SOURCE PROGRAM}

\subsection{Algoritma Pencarian Rute (Pathfinding)}

Semua algoritma berbagi struktur \texttt{SearchNode} yang menyimpan state saat ini, biaya jalur $g(n)$, nilai evaluasi $f(n)$, serta riwayat gerak. Priority queue diimplementasikan sebagai min-heap kustom agar pemilihan simpul prioritas tertinggi berjalan dalam $O(\log n)$.

Berikut adalah implementasi A* sebagai contoh utama. GBFS hanya berbeda pada baris perhitungan \texttt{FCost} (diganti dengan nilai $h$ saja), sedangkan UCS menetapkan \texttt{FCost = GCost}.

\begin{lstlisting}[language=Go]
func AStar(puzzle *engine.Puzzle, heuristic HeuristicFunc) (*SolveResult, error) {
    start := time.Now()
    initialState := puzzle.InitialState()

    h0, err := heuristic(puzzle, initialState)
    if err != nil {
        return nil, err
    }

    frontier := &MinHeap{}
    frontier.Push(&SearchNode{
        State: initialState, GCost: 0, FCost: h0,
        Moves: []string{}, Slides: []engine.SlideResult{},
    })

    visited := map[engine.State]bool{}
    iterations := 0

    for !frontier.IsEmpty() {
        current := frontier.Pop()
        if visited[current.State] {
            continue
        }
        visited[current.State] = true
        iterations++

        if puzzle.IsGoalState(current.State) {
            return buildResult(current, iterations, time.Since(start)), nil
        }

        for _, dir := range searchDirections {
            slide, ok, err := puzzle.Slide(current.State, dir)
            if err != nil {
                return nil, err
            }
            if !ok || visited[slide.NextState] {
                continue
            }
            nextG := current.GCost + slide.PathCost
            nextH, err := heuristic(puzzle, slide.NextState)
            if err != nil {
                return nil, err
            }
            frontier.Push(&SearchNode{
                State:  slide.NextState,
                GCost:  nextG,
                FCost:  nextG + nextH,
                Moves:  appendMove(current.Moves, dir),
                Slides: appendSlide(current.Slides, slide),
            })
        }
    }
    return notFound(iterations, time.Since(start)), nil
}
\end{lstlisting}

Algoritma bonus IDA* menggunakan DFS berulang dengan threshold pada nilai $f(n)$. Berikut fungsi rekursifnya:

\begin{lstlisting}[language=Go]
func idaStarDFS(
    puzzle *engine.Puzzle, state engine.State,
    gCost, threshold int, heuristic HeuristicFunc,
    pathVisited map[engine.State]bool,
    moves []string, slides []engine.SlideResult,
) (*SolveResult, int, int, error) {
    h, err := heuristic(puzzle, state)
    if err != nil {
        return nil, 0, 0, err
    }
    fCost := gCost + h
    if fCost > threshold {
        return nil, fCost, 0, nil
    }
    if puzzle.IsGoalState(state) {
        return &SolveResult{
            Found: true, Moves: moves,
            Slides: slides, TotalCost: gCost,
        }, 0, 1, nil
    }

    minNext := unreachableHeuristic
    iterCount := 1

    for _, dir := range searchDirections {
        slide, ok, err := puzzle.Slide(state, dir)
        if err != nil {
            return nil, 0, iterCount, err
        }
        if !ok || pathVisited[slide.NextState] {
            continue
        }
        pathVisited[slide.NextState] = true
        childResult, childNext, childIter, err := idaStarDFS(
            puzzle, slide.NextState, gCost+slide.PathCost, threshold,
            heuristic, pathVisited,
            appendMove(moves, dir), appendSlide(slides, slide),
        )
        iterCount += childIter
        pathVisited[slide.NextState] = false
        if err != nil {
            return nil, 0, iterCount, err
        }
        if childResult != nil {
            return childResult, 0, iterCount, nil
        }
        if childNext < minNext {
            minNext = childNext
        }
    }
    return nil, minNext, iterCount, nil
}
\end{lstlisting}

\subsection{Fungsi Heuristik}

Ketiga heuristik menggunakan antarmuka fungsi \texttt{HeuristicFunc} yang sama sehingga dapat dipakai secara seragam oleh A*, GBFS, dan IDA*.

\textbf{H1 --- Jarak Manhattan:}

\begin{lstlisting}[language=Go]
func HeuristicManhattan(puzzle *engine.Puzzle, state engine.State) (int, error) {
    if err := validateHeuristicInput(puzzle, state); err != nil {
        return 0, err
    }
    current := state.Actor
    total := 0
    for idx := state.NextCheckpoint; idx < puzzle.CheckpointCount(); idx++ {
        target := puzzle.CheckpointOrder[idx]
        total += manhattanDistance(current, target)
        current = target
    }
    total += manhattanDistance(current, puzzle.Goal)
    return total * puzzle.MinWalkableCost, nil
}
\end{lstlisting}

\textbf{H2 --- Minimum Slide (BFS ringan ke target berikutnya):}

\begin{lstlisting}[language=Go]
func HeuristicMinimumSlide(puzzle *engine.Puzzle, state engine.State) (int, error) {
    if err := validateHeuristicInput(puzzle, state); err != nil {
        return 0, err
    }
    if targetSatisfied(puzzle, state, state) {
        return 0, nil
    }
    type bfsNode struct {
        state engine.State
        depth int
    }
    queue := []bfsNode{{state: state, depth: 0}}
    visited := map[engine.State]struct{}{state: {}}
    for len(queue) > 0 {
        current := queue[0]
        queue = queue[1:]
        for _, direction := range heuristicDirections {
            result, ok, err := puzzle.Slide(current.state, direction)
            if err != nil {
                return 0, err
            }
            if !ok {
                continue
            }
            nextState := result.NextState
            if targetSatisfied(puzzle, state, nextState) {
                return (current.depth + 1) * puzzle.MinWalkableCost, nil
            }
            if _, exists := visited[nextState]; exists {
                continue
            }
            visited[nextState] = struct{}{}
            queue = append(queue, bfsNode{state: nextState, depth: current.depth + 1})
        }
    }
    return unreachableHeuristic, nil
}
\end{lstlisting}

\textbf{H3 --- Dijkstra Lokal ke target berikutnya} menggunakan priority queue dan menyimpan hasilnya ke dalam cache per-puzzle agar tidak dihitung ulang untuk state yang sama. Implementasi lengkapnya tersedia di \texttt{src/backend/algorithm/heuristic.go}.

func (p *Puzzle) Slide(state State, direction string) (SlideResult, bool, error) {
    delta, exists := moveDeltas[direction]
    if !exists {
        return SlideResult{}, false, fmt.Errorf("arah tidak valid: %q", direction)
    }

    current := state.Actor
    nextCheckpoint := state.NextCheckpoint
    path := make([]Position, 0, p.Rows+p.Cols)
    passedCheckpoints := make([]int, 0, 4)
    totalCost := 0
    moved := false

    for {
        next := current.Add(delta)

        // Batas papan berlaku sama dengan dinding
        if !p.InBounds(next) {
            if !moved {
                return SlideResult{}, false, nil
            }
            return p.buildSlideResult(direction, state, current,
                path, totalCost, passedCheckpoints, nextCheckpoint)
        }

        token := p.Cell(next)

        if token == TileWall {
            if !moved {
                return SlideResult{}, false, nil
            }
            return p.buildSlideResult(direction, state, current,
                path, totalCost, passedCheckpoints, nextCheckpoint)
        }

        // Lintasan melewati lava selalu ilegal
        if token == TileLava {
            return SlideResult{}, false, nil
        }

        // Checkpoint di luar urutan berlaku sebagai dinding
        checkpoint, isCheckpoint := parseCheckpointToken(token)
        if isCheckpoint && checkpoint > nextCheckpoint {
            if !moved {
                return SlideResult{}, false, nil
            }
            return p.buildSlideResult(direction, state, current,
                path, totalCost, passedCheckpoints, nextCheckpoint)
        }

        current = next
        moved = true
        path = append(path, current)
        totalCost += p.CostAt(current)

        if isCheckpoint && checkpoint == nextCheckpoint {
            passedCheckpoints = append(passedCheckpoints, checkpoint)
            nextCheckpoint++
        }
    }
}
\end{lstlisting}
